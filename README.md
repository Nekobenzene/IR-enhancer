# 红外灰度色标增强工具

导入红外灰度图片（**PNG / JPG**），按固定物理温度做连续色标增强，实时预览，
单张 / 批量导出彩色图片，色标可存为 JSON。

**双击 `index.html`** 即可使用：单文件、零依赖，用 Edge 或 Chrome 打开
（在文件上右键 →「打开方式」→ Edge / Chrome）。不需要 Python，不需要安装任何东西，不需要联网。
桌面与手机 / 平板浏览器都能用：窄屏会自动切换成单栏布局并支持触摸手势。

**预设色标是配置文件驱动的**：`index.html` 里没有任何预置数据，增删 / 修改预置只改 `PreSet/`
目录下的配置（一预设一个文件 + 一份清单），**不需要改 `index.html`，也没有构建步骤**。

### 目录结构

```
灰度红外增强工具/
├── index.html            ← 工具本体（单文件，双击即用；改了名字也能用）
├── README.md             ← 本文档
├── fixtures/             ← 自检用的基准图片与 expected.json（开发用，日常使用不需要）
├── PreSet/               ← 预设色标配置（打开页面时读，改了立刻生效）
│   ├── manifest.js       ←   清单：按顺序列出要载入哪些预置文件
│   └── *.js              ←   一条预置一个文件（一行包装 + 一段色标 JSON）
└── build/                ← 开发用的全部脚本（日常使用完全不需要）
    ├── test_html_core.mjs      核心算法自检（Node，不需要浏览器）
    ├── test_html_browser.mjs   真实 Chrome 端到端自检（输出到 build/.test_tmp/）
    ├── test_gen_fixtures.py    重新生成 fixtures/ 里的基准图片（Python + Pillow，可选）
    └── test_verify_exports.py  用 Pillow 交叉校验导出物（可选）
```

`build/` 里的脚本按约定找上层目录：主文件 `<项目>/index.html`、基准图片 `<项目>/fixtures/`、
预置色标 `<项目>/PreSet/`，所以整个「灰度红外增强工具」文件夹可以随便搬位置
（也兼容「脚本与 index.html / fixtures 同级」的旧布局）；
也可以用环境变量 `IR_HTML` / `IR_FIXTURE_DIR` / `IR_TEST_OUT` 显式指定。
`PreSet/` 要与 `index.html` 放在一起；只拷走 `index.html` 也能用，只是预设列表为空（日志会说明原因）。

`build/.test_tmp/` 是自检运行时生成的输出目录（桌面 + 手机 / 手机横屏 / 平板的界面截图、导出物、
临时页面、Chrome 临时 profile），随时可以整个删掉。

## 功能

界面为简体中文、浅色主题，布局为：菜单栏 / 图片预览 / 色标柱 + 节点卡片 / 图片列表 / 底部日志。
窄屏（手机 / 平板竖屏）会自动变成**自上而下的单栏**并整页滚动，详见下面的
「[移动端 / 触屏适配](#移动端--触屏适配响应式)」。

中间一列在「色标范围」以下再分成两栏：**左边是贯穿整列高度的细色标柱（宽 16 px，直接落在灰色背景上，
不套白底），右边是节点卡片列表**。图片列表在最右侧（270 px）。

### 图片温度：黑色温度 / 白色温度（属于图片，不属于色标）

- 预览区标题栏里只有**两个温度**（位于标题与「重置视图」之间，默认 **黑色 50°C / 白色 -85°C**）：
  **黑色温度** = 灰度 0（纯黑）对应多少度，**白色温度** = 灰度 255（纯白）对应多少度。
  映射是 `T = 黑色温度 + (白色温度 - 黑色温度) × p / 255`（p = 0..255）。
- **不要求谁大谁小**：白色温度高于黑色温度同样合法，也就是**浅色代表高温**（反色红外图）也支持。
  程序内部**比较两个温度的大小**，把较大的当上限、较小的当下限，刻度、亮度换算与范围判断都用这两个值；
  两个温度填成一样也允许（整幅图一个温度）。除「必须是数字且落在 1 K ~ 2000 K」外没有任何约束。
- **切换色标不会改变像素代表多少度**，图片温度始终固定，和色标完全解耦。
- **所有 legend 的温度轴都等于图片两端的温度**（第二列的色标柱、以及「我的色标 / 管理色标」
  弹窗里的横向 legend 都共用同一根温度轴，方便横向比较不同色标）：
  - 色标比图片温度区间**窄**时，两端节点的颜色会被**拉伸**到图片两端的温度；
  - 色标比图片温度区间**宽**时，只显示图片温度区间那一段，**超出部分被截断**。
  - 竖向色标柱**顶端永远是黑色端、底端永远是白色端**（柱子上就是各灰度对应的温度），
    横向 legend 则是**温度轴**（左低右高）—— 所以浅色代表高温时，竖向柱子是「上冷下热」。
- 色标自身的范围仍会显示在第二列的只读信息里（例如 `50°C ~ -85°C（由最高温 / 最低温节点决定）`），
  但它只是说明，不影响 legend 的坐标轴。
- 单位 °C / °F / K / Brightness（亮度 = 灰度值本身：黑色端 0、白色端 255）只做显示换算；
  所有输入框只填数字，不带单位，单位取当前全局温标。
- 内部一律以 Kelvin 存储，保存精度 0.01 K（银行家舍入）。

### 色标节点

- 程序启动时的默认色标是：**一个保留节点 50°C 黑色 + 一个普通节点 -85°C 白色**
  （与默认图片温度配对，整条范围正好是黑到白）。想换成一模一样的另一条，导入 **预设 → IR-BW** 即可。
- 想从零搭一套色标，导入 **预设 → 空白**（单个白色保留节点，整幅纯白）。
- **保留节点（卡片上有「保留」标记）只禁止删除**，位置和颜色都能改；它不参与批量选择，
  「全选」也不会勾中它，无论怎么删都至少会留下它。
- 连续色标：节点之间 RGB 三通道分别线性插值；**Legend 与图片着色使用同一个 ColorMapper**。
- **温度相同的两个节点**会合并成一组共边框并置的卡片，分界线上骑一个双箭头小按钮，
  点它即可交换两者顺序（也就是改变硬跳变方向）。
- 节点支持新增 / 编辑（原生取色器 + HEX + RGB 三向同步，失焦校验回退）、选择模式批量删除。

### 图片

- 支持 **PNG 与 JPG / JPEG**；一次可选多张；只能通过「添加图片」按钮打开 Windows 原生文件选择器，
  不支持拖拽。
- 允许重复导入同一张图片，显示名自动加后缀：`image.png` → `image(1).png` → `image(2).png`。
- 图片列表在窗口最右侧：缩略图保持比例不裁剪、文件名过长省略并带悬停提示、当前预览行浅蓝底色。
- 普通模式单击切换预览（双击无额外动作）；选择模式点击任意位置只切换勾选、不切换预览。
- 预览默认 Fit、滚轮缩放、拖动平移，「重置视图」只重置缩放平移。
- 图片按需从磁盘读取，只有当前图片会驻留内存。

### 操作入口

菜单栏只保留「帮助」与右侧「退出」，其余操作都放在就近的下拉按钮组里：

| 按钮 | 位置 | 包含 |
| --- | --- | --- |
| 打开色标 | 第二列（色标）最上方 | **预设** / 我的色标 / 从设备中导入 / 输入色标 |
| 管理色标 | 第二列，夹在「打开色标」与「保存色标」之间 | 我的色标（管理弹窗）/ 从设备导入（收进色标库） |
| 保存色标 | 第二列（色标）最上方 | 保存 / 另存为 |
| 导出图片 | 图片列表上方 | 单张导出（当前预览）/ 批量导出（已勾选的图片） |

两个「从设备…」的区别：**打开色标 →「从设备中导入」**是把文件载入成当前正在编辑的色标；
**管理色标 →「从设备导入」**是把设备上的 JSON 配置直接收进本地色标库（可多选文件，按时间戳覆盖或新增，
不改动当前色标）。

### 色标身份与色标库

- **每个色标都有一个毫秒级创建时间戳**（`created`），它是色标的**唯一身份**，一经创建永不修改。
  名称只是标签，可以随时改。
- **保存** = 写入浏览器本地色标库（localStorage），**不会覆盖设备上已打开的文件**。
  匹配完全按时间戳：同一条色标就覆盖，新色标就新增；改名后保存仍然是同一条记录。
- **另存为** = 导出一份 JSON 到设备（Windows 原生另存为 / 下载）。
- **导出到剪贴板** = 「我的色标 / 管理色标」弹窗底部的一个按钮，**单选一条之后才可用**（勾了「多选」就变灰）。
  点一下把这条色标的 JSON 复制走，内容与「另存为」的文件**完全一样**，可直接粘到聊天窗口 / 记事本，
  或者用下面的「输入色标」再贴回来。复制成功后按钮显示「已复制」（蓝色高亮），**最多停留 2 秒**，
  随后在 0.3 秒内渐隐并切回「导出到剪贴板」；这期间**一换选中的色标**（或切多选 / 删除 / 关弹窗）
  就**立刻**切回原文案并中断渐隐，弹窗每次打开也都是原文案。
  失败（浏览器不允许或窗口没焦点）会弹提示并建议改用「另存为」。
- **从设备中导入** = 读取一个 JSON 文件；文件里没有 `created` 时会补上当前时间戳。
- **输入色标**（打开色标 → 输入色标）= 弹出一个文本框，把一段色标 JSON **粘进去按确定就直接载入**为当前色标，
  不用先存成文件。校验是**就地**做的：JSON 格式错 / 字段缺失 / 颜色写法不对 / 温度超出 1 K ~ 2000 K /
  同一位置超过 2 个节点，都会在文本框下方用红字写明原因，**弹窗不关、文本不丢**，改完再确定即可。
  文本里没有 `created` 时会补当前时间戳；当前色标有未保存修改时同样会先问「是否继续」；取消 / Esc 不改动任何东西。
- **我的色标** = 弹出本地色标库，自上而下每条显示：
  **横向 legend（左低温、右高温，只标两端温度，不画细刻度）+ 色标名称 + 创建时间（创建于YYYYMMDD HH:mm:SS）**。
  横向 legend 同样以**当前图片两端的温度**为温度轴，所以列表里所有色标可以直接横向对比。
  点选一条后按「确定」载入（弹窗底部左「取消」右「确定」，中间是「导出到剪贴板」）。
- **管理色标 → 我的色标** = 同一个弹窗的增强版：右上角有「多选」勾选框与「删除」按钮。
  勾上「多选」后每条左侧出现勾选框，同时多出「全选 / 全不选」两个按钮；
  勾选至少一条即可**从本地库永久删除**，删除完成后会自动退出多选状态。
  不勾「多选」时就是单选，选一条后「导入」与「删除」同时可用，可单独导入或删除。
  弹窗底部是左「取消」右「导入」，「导出到剪贴板」在它们中间（多选状态下禁用）。
- **预设**（打开色标 → 预设）= 弹出**配置文件里的**预置色标列表，样式与「我的色标」一样，
  底部是左 **取消** 右 **导入**；选中一条按「导入」就载入成当前色标。列表固定把 **空白** 放第一位
  （单个白色保留节点，整幅纯白，用来从零搭一套色标 —— 也就是原来「新色标」的用法）。
  随工具发行的 9 条：空白 / IR-BW / IR-BD-ex / IR-BD / IR-CA / IR-CC / IR-OTT / IR-RAMMB / IR-RBTOP。
  - **预置文件里没有 `created`**：`created` 只在**导入的那一刻**按当前时间生成，
    所以每导入一次都是一条**全新的**色标，可以再「保存」进本地色标库；之后再改它删它都不影响预置本身。
  - 预置**不占本地库**：程序启动时不再往 localStorage 里写任何东西，列表每次打开页面时从
    `PreSet/` 读配置（见下面「[预置色标是配置文件](#预置色标是配置文件驱动的)」）。
  - 当前色标有未保存修改时，选完预置按「导入」会先问一次「是否继续」，取消则什么都不变。
- 按钮配色统一：**「确定 / 导入 / 保存 / 继续」类可用时为 Windows 经典蓝，
  「删除」类可用时为 Windows 经典红，禁用时都是经典浅灰。**

### 预置色标是配置文件驱动的

`index.html` 里**没有任何预置数据**（连一个节点都没有）：预置是每次打开页面时从 `PreSet/` 目录读进来的。

| 文件 | 作用 |
| --- | --- |
| `PreSet/manifest.js` | 清单：`window.IR_PRESET_FILES = ['空白.js', 'IR-BW.js', …]`，**列出的顺序就是弹窗里的顺序** |
| `PreSet/<名字>.js` | 一条预置：一行 JS 包装 + 一段色标 JSON；**文件名必须与里面的 `name` 一致** |

一个预置文件长这样（数据部分与「另存为」导出的 JSON 完全一致，只是不带 `created`）：

```js
(window.IR_PRESETS = window.IR_PRESETS || []).push({
  "name": "IR-BW",
  "nodes": [
    { "temperature_k": 323.15, "color": "#000000", "pinned": true },
    { "temperature_k": 188.15, "color": "#FFFFFF" }
  ]
});
```

- **新增一套预置**：复制一份现有的 `.js` 改数据（文件名 = `name`），再在 `manifest.js` 里加一行。
  **不用动 `index.html`**，也没有任何生成 / 构建步骤。
- **修改 / 删除**：直接改 / 删对应的文件（删除时把清单里的那一行也删掉）。
- **为什么是 `.js` 而不是 `.json`**：双击打开时页面源是 `file://`，浏览器禁止 `fetch` 与
  `XMLHttpRequest` 读本地文件（实测 `fetch` 报 `Failed to fetch`、XHR 报 `Failed to load`），
  只放行 `<script src>` 载入的脚本 —— 所以配置写成「一行 JS 包装 + 一段 JSON」，
  这样**双击就能用，既不需要本地服务器，也不需要构建**。
- **出错时的表现**：清单缺失 / 某个文件载入失败 / 内容非法（温度越界、颜色写法不对、同一位置超过 2 个节点）→
  **跳过该条并把原因写进运行日志**，预设列表为空（弹窗里有提示）；
  文件名与 `name` 不一致、预置里写了 `created` → 只在日志里提示（`created` 一律忽略）。
  **任何情况下都不会退回硬编码数据。**
- 两条自检都会核对「清单 ↔ 目录 ↔ 页面里的列表」三者一致，并逐节点比对配置文件与页面里的预置数据。

### 其它行为

- **单张导出**导出的是**当前预览的那张图片**。
- **批量导出**导出的是**图片列表里已勾选的图片**；一张都没勾选时会提示「请选择图片」。
  要勾选图片，先打开图片列表顶部的「选择」开关。
- 没勾选任何条目就点「删除选中」时，会提示「请选择图片」/「请选择节点」，不会静默无反应。
- **新建色标 / 我的色标 / 从设备中导入**时，如果当前色标有未保存的修改，会先弹窗确认，取消则保持原样。
- 有未保存修改时标题显示 `*`，关闭页面前也会提醒保存。
- **菜单栏的「帮助」点一下就直接打开使用说明**（没有二级菜单，也不再有单独的「关于」）：
  内置一份完整的中文说明书（Markdown 源写在页面里，打开时现场渲染成 HTML），共 **12 章、13 个小节**。
  左侧目录**只列章名**（加粗）且**默认全部收起**，带 `▸` 的章点一下才会展开它的小节
  （`▾` 再点收起，同时只展开一章）；右侧正文里标题 / 表格 / 代码块 / 引用 / 列表 /
  行内代码与粗体都已渲染。

### 导出与配置

- **导出格式跟随源文件**：PNG 进 PNG 出（无损、保留 Alpha）；JPG 进 JPG 出（质量 0.92，无 Alpha）。
- 单张导出：Windows 原生「另存为」，保持原分辨率。
- 批量导出：选目标位置 → 修改文件夹名（默认 `IR_Enhance_YYYYMMDD_HHMMSS`，同名自动 `(1)(2)…`）
  → 进度条 + `正在处理 37 / 120：filename.png`，可取消；单个文件失败会跳过并汇总原因；
  导出期间锁定界面。

### 界面设计系统

界面按 **Fluent 2（Windows 11）浅色工具语言** 实现，单文件内自带设计令牌，不依赖任何外部资源：

- **字体**：拉丁优先栈（Segoe UI Variable / Segoe UI）+ 中文回退（Microsoft YaHei UI）；
  所有温度读数、输入框、刻度、日志一律 **表格数字（tabular-nums）+ 等宽栈**，数值变化时不会左右跳动。
- **颜色**：单一冷灰族 + **单一强调色**（`#0f6cbd`）；阴影一律带蓝灰色调，不用纯黑投影。
- **形状**：统一圆角体系，控件 4px / 面板与卡片 6px / 对话框 8px。
- **状态**：完整实现 hover / active（下沉 1px）/ focus-visible（2px 强调色焦点环）/ disabled；
  加载态为扫光骨架，空状态说明如何开始，错误用对话框而不是 `alert`。
- **可访问性**：`color-scheme: light` 锁死浅色（系统深色模式下控件也不会变黑）；
  尊重系统「减少动态效果」，开启后所有过渡与动画关闭。
- **透明度可视化**：预览区用棋盘格显示 Alpha，透明区域一眼可见。
- Legend 刻度在高度不足时**自动抽稀标签**（刻度线保留），避免文字挤成一团；
  **两端温度一定会标注**：端点若落在整十刻度上就随刻度一起标，不在整十数上（例如 63 / -92）会额外补标，
  且用加粗与深色和普通刻度区分。亮度单位下这两端自然就是 `0`（黑色端）与 `255`（白色端）。

### 移动端 / 触屏适配（响应式）

同一个 `index.html` 兼顾桌面与手机，靠 CSS 断点 + 触屏手势实现，**没有第二份移动版文件**：

- **断点**：`> 1180px` 三栏（桌面原样）；`≤ 1180px` 三栏收窄（两侧 300 / 236 px）；
  `≤ 900px` 改成**单栏纵向流**（预览 → 色标 → 图片列表 → 日志），整页上下滚动；
  `≤ 560px` 手机细节（预览标题行换行、下拉菜单不出屏、输入框字号 ≥ 16px 以免 iOS 聚焦时放大整页）。
  **桌面宽屏 + 鼠标下的布局与交互保持原样**。
- **高度**：外壳用 `100dvh`（手机上地址栏收起 / 展开时不跳动），预览固定约半屏高、色标列给确定高度，
  于是节点列表 / 图片列表 / 日志各自在内部滚动，页面不会被撑成无限长。
- **触屏手势**（`pointer` 为触摸时）：**单指拖动 = 平移**，但 **Fit 状态下单指上下滑是滚动页面**
  （只有放大之后画布才接管拖动，不会「卡」在预览上滚不动）；**双指捏合 = 缩放**，锚点是两指中点
  （中点在图上按住的那个像素不动）；**双击 = Fit ↔ 2.5 倍**。
  鼠标仍是滚轮缩放 + 左键拖动，行为完全不变。
- **触控尺寸**：`pointer: coarse`（真正的触屏设备）下按钮 / 菜单项 / 卡片行高统一 ≥ 36 px，复选框与色块同步放大，
  同一位置两个节点的「⇅ 交换」按钮从 22 px 放大到 32 px；鼠标设备即使窗口很窄也保持桌面尺寸。
- **弹窗**：`≤ 900px` 时最大 `94vw × 92dvh`；「使用说明」的左右分栏改成上下（目录在上、正文在下）；
  手机上按钮行可换行，「确定 / 取消 / 导出到剪贴板」不会被挤出屏幕。
- **安全区与滚动**：`viewport-fit=cover` + `env(safe-area-inset-*)` 适配刘海屏 / 圆角屏；
  `overscroll-behavior: none` 关掉「下拉刷新」，避免拖预览时误触发。

### 浏览器带来的三点差异

1. **PNG 由本程序自行解码 / 编码**（不用 canvas），因此灰度与 Alpha **逐字节精确**。
   浏览器 canvas 会做预乘 Alpha 往返，半透明像素会产生 ±1~2 灰度误差（≈0.5~1°C），
   所以 PNG 的读写都绕开了 canvas。
   **JPG 走浏览器解码**：JPG 本来就没有 Alpha（整幅不透明），不透明像素的 canvas 往返是无损的，
   所以灰度读取同样精确，损失的只有 JPG 本身的压缩误差。
2. **批量导出**：Edge / Chrome 支持原生「选择文件夹」，程序会在其中新建输出文件夹；
   若浏览器不支持，则改打包成同名 ZIP 下载（解压后即为该文件夹）。
3. **菜单栏**是网页内的仿系统菜单栏（只保留「帮助」与右侧「退出」）；「退出」受浏览器限制
   只能关闭标签页，因此按浏览器规范改为关闭前提醒保存。

### 支持的图片

- 输入 **PNG**：8 位 / 16 位灰度、灰度+Alpha、RGB、RGBA、调色板（非隔行扫描）；
  灰度值统一按 0..255 参与温度换算（16 位按 ÷257 缩放）。
- 输入 **JPG / JPEG**：按整幅不透明处理（Alpha 全为 255）；若三个分量相同取该值，否则取亮度
  `0.299R + 0.587G + 0.114B`。
- 输出：源是 PNG 则输出 8 位 RGBA PNG（无损、Alpha 原样）；源是 JPG 则输出 JPEG（质量 0.92）。
  两者都保持原分辨率与原文件名。

## 需求中若干处的实现取舍

1. **Brightness（亮度）刻度**：按每 10°C 一个整数刻度换算；两端标注在亮度单位下自动就是顶部 `0`、
   底部 `255`，不需要额外特判。
2. **批量导出的文件夹名**：先选目标位置，再用输入框修改默认名
   `IR_Enhance_YYYYMMDD_HHMMSS`；同名自动追加 `(1)(2)…`，绝不覆盖。
3. **重复导入的输出文件名**：同一 PNG 可重复导入，导出使用显示名，避免同批导出互相覆盖；
   无重复时即原文件名。
4. **「同一位置」的判定**：按 0.01 K（保存精度）比较，因此 0.001 K 的差异视为同一位置，
   保证存盘再打开后不会变成 3 个重合节点。
5. **图片温度与色标解耦**：温度是**图片的属性**（预览区标题旁），改它只影响「灰度→温度」，
   不动任何色标节点；色标不再有温度字段，范围完全由两端节点决定。
6. **legend 的温度轴**：一律等于**图片两端的温度**。色标窄于图片温度区间时把两端节点色**拉伸**到两端温度，
   色标宽于图片范围时只显示图片范围内那一段（**截断**）。色标自身范围只作为只读信息显示。
7. **JSON 字段**：色标配置只含 `name`、`created`（毫秒时间戳）与 `nodes`
   （每个节点 `temperature_k` / `color`，保留节点多一个 `"pinned": true`）。
   **旧配置里遗留的 `range` 字段会被直接忽略**，缺 `created` 时补当前时间。
8. **Legend 刻度**：默认每 10°C 一个整数刻度；当图片温度区间很窄或很宽时，自动换挡
   （1/2/5/10/20/25/50/100/200）以保证刻度数量在 3 ~ 14 之间
   （默认范围 50 ~ -85 即 10°C 一格，共 14 个整点刻度）。
   **黑色端与白色端的温度始终标注**：落在整点网格上就随刻度一起标，不在网格上（例如 63 / -92）额外补标并加粗。
9. **保留节点**：只禁止删除（且「全选」不会勾中它、至少会留下它），位置与颜色照常可改。
10. **色标库存储位置**：用 `localStorage` 的 `ir_enhancer.scales.v1` 键保存一个数组；
    浏览器禁用本地存储时会给出明确提示并拒绝保存（不会静默失败）。
11. **取色精度与硬跳变**：颜色映射按 **0.01 K**（= 配置文件精度）对齐节点位置，
    所以「屏幕上的色标」与「保存后重新打开 / 弹窗里那条」逐灰度完全一致。
    硬跳变处上方取靠上的那个节点色、下方取**靠下的那个节点色**；
    最冷端的硬跳变（两个节点都在最低温）在冷端拉伸区同样取**最下方节点**的颜色，
    横向 legend、竖向 legend 与图片着色三者一致。
12. **剪贴板**：优先用异步剪贴板 API（`navigator.clipboard.writeText`），不可用时退回
    隐藏 textarea + `document.execCommand('copy')`；两条路都失败才弹提示，并建议改用「另存为」。
    复制出去的内容 = `scaleToText()` 的结果，与「另存为」写出的文件逐字节相同。
13. **「输入色标」的就地校验**：不动当前色标，先在弹窗里 `JSON.parse` + `scaleFromObject`，
    出错只把原因显示在文本框下方（弹窗不关、文本不丢），校验通过才替换当前色标。
14. **预设为什么是「配置文件 + 一行 JS 包装」**：`index.html` 要保持「双击即用」，而 `file://`
    下浏览器不允许 `fetch` / XHR 读本地文件，`<script src>` 又是唯一能读本地配置的方式（实测见上），
    所以一个预置 = 一个 `.js` 文件 = 一行 `push({…})` 包装 + 一段（与「另存为」同格式的）JSON；
    清单单独放 `PreSet/manifest.js`，这样增删预置不用碰 `index.html`，也不需要任何生成脚本。
    代价是「一个预置一个文件」需要有人维护清单 —— 但换来的是纯配置驱动、可读的 diff 和零构建。
15. **只填「黑色温度 / 白色温度」，不填上限 / 下限**：用户只需要回答「灰度 0 是多少度、灰度 255 是多少度」，
    不必先想清楚哪一头更热，所以界面上没有「上限 / 下限」、也没有「上限必须大于下限」这类校验。
    程序在 `setRange(blackK, whiteK)` 里 `Math.max / Math.min` **比较一次**，把上限 / 下限算出来，
    刻度、亮度换算、范围判断继续用这两个值 —— 于是「浅色代表高温」只是把两个框反过来填，
    其余算法一行都不用改。两个端点温度相同时（`K_SPAN === 0`）整幅图就是那个温度，
    `pToKelvin / kelvinToP` 都做了除零保护。
